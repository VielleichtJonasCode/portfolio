# umbenennen (z.B. "Mein-Projekt") und in der Kopie diese Datei ausfüllen.
# Ordner mit "_" am Anfang werden von update_website.py ignoriert, die Kopie
# mit normalem Namen taucht danach automatisch auf index.html und
# alle-projekte.html auf, sobald "python3 update_website.py" läuft.
# Bilder unten im Format "dateiname.png Alt-Text Bildunterschrift", getrennt
# durch senkrechte Striche; die Datei muss im bilder/-Ordner dieses Projekts liegen.
#
# 3D-Live-Ansicht: STL/OBJ/DAE/URDF-Dateien in einen "modelle/"-Ordner in diesem
# Projektordner legen (Ordner ggf. selbst anlegen) — beim nächsten
# "python3 update_website.py" kopiert das Skript AUTOMATISCH den Viewer aus
# "portfolio vorlagen/3d-viewer/" nach 3d-viewer/ in diesem Projektordner und
# bettet die Modelle darin ein (kein Upload zur Laufzeit, kein Server, nichts
# manuell kopieren). Danach unten bei "3d-viewer:" den Pfad
# "3d-viewer/3d-viewer.html" eintragen, damit der Button erscheint.
# Überschrift/Text im Viewer kommen automatisch von title/tagline hier — für
# eigenen Wortlaut optional viewer_titel:/viewer_text: ergänzen.
#
# Zusätzliche Buttons neben Source/Live/3D-Ansicht: weiter unten im Abschnitt
# "## Links" eine Zeile pro Button im Format "Beschriftung Senkrechter-Strich
# URL", optional gefolgt von zwei weiteren mit Senkrechten-Strichen
# abgetrennten Zahlen für feste Breite und Höhe in Pixeln. Zeilen mit "#" am
# Anfang werden dabei ignoriert (zum Testen/Auskommentieren).
# Siehe projekte/Satellite-Tools/projekt.txt für ein aktives Beispiel.
#
# Button MITTEN im Beschreibungstext (### Ziel usw., nicht in einem
# ##-Abschnitt): "Button:Beschriftung:URL" irgendwo in einem Satz/Listenpunkt
# schreiben — wird automatisch zum echten Button an genau dieser Stelle. Die
# URL darf dabei kein Leerzeichen enthalten. Für einen normalen Text-Link
# (kein Button, nur unterstrichenes Wort) stattdessen [Beschriftung](URL)
# schreiben.
#
# Feste Beschreibungsstruktur: jedes Projekt soll die Überschriften
# ### Ziel, ### Ablauf, ### Ergebnis enthalten (in dieser Reihenfolge),
# plus optional einen vierten, frei benannten Punkt (z.B. "Roadmap",
# "Learnings", "Architektur" — was auch immer passt). Fehlt eine der drei
# Pflicht-Überschriften, gibt update_website.py beim Bauen nur eine Warnung
# aus (bricht nicht ab) — so bleibt die Struktur überall konsistent.
